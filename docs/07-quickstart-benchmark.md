# Quickstart Open-Source Benchmark (Pets / SROIE / CUB / TextVQA)

> A reproducible benchmark for open-source users: 4 open datasets × 8 automatic prompt optimization (APO) methods
> (sroie as a 6-method subset), unified Qwen3.5-9B weights, unified budget tiers and
> judging protocol. The study is numbered by experiment as in a tech report (E = experiment):
> E1 two-backend parity, E2 three-seed stability, E3 cost profiles; the §3/§5 tables are
> machine-regenerated by
> `scripts/aggregate_bench_results.py` from the Qwen3.5-9B quickstart GPU runs
> (90 E2 cells over 3 seeds × 4 datasets, plus 6 E1 arm cells; every run completed).
>
> **Authority note**: this doc is the quickstart mini-split tier (σ≈3 percentage
> points (pp)), the out-of-the-box / backend-parity record. The **single
> authoritative effect scoreboard** is docs/08 (full-scale splits, seven models, all
> 8 methods per dataset, regenerated from the bench run set); where the two disagree,
> docs/08 is the published reading.

## 1. Datasets and tasks

Data is built by `eyas prepare` (shipped in the package as `eyas.prepare`) into
`datasets/quickstart/<ds>/`
(download channels: HF direct → hf-mirror → ModelScope, with automatic fallback via
`--source auto`; `--dataset` is required: pick the datasets explicitly, `all`
builds all six). pets / cub use a **within-group multiple-choice** protocol: choices
is the class list within the group the sample belongs to (not the full class pool),
with splits built per group (`McqTask` grouped-sampling semantics); sroie follows the
KIE protocol (zero judge, rule-based scoring).

The quickstart study (E1/E2/E3, the §3-§5 tables) covers the **four E2 benchmark
columns** below. The prepare script and the config family additionally ship cells
that are not quickstart E2 columns; they join the published bench matrix at bench
scale only (docs/08).

**E2 benchmark columns** (the §3-§5 tables):

| Dataset | Source | Task | Groups and choices | train / test | Primary metric |
| --- | --- | --- | --- | --- | --- |
| pets | Oxford-IIIT Pet (timm/oxford-iiit-pet) | mcq breed selection | two groups: cat (12 breeds) / dog (25 breeds) | 74 / 111 | accuracy |
| cub | CUB-200-2011 snapshot | mcq bird-species selection | 8 bird groups (7+7+7+7+7+7+7+6, 55 species in total) | 110 / 220 | accuracy |
| sroie | SROIE receipts | kie entity extraction | single group; four fields company / address / date / total | 100 / 100 | field_acc (aux strict_acc / char_sim) |
| textvqa | TextVQA scene-text QA (`lmms-lab/TextVQA`, labeled-val slice) | vqa open-ended answering | none — no variants exist for open-ended QA (identity protocol); VQAv2 soft accuracy `min(1, eq/3)` over 10 human answers, zero judge | 100 / 100 | accuracy |

**Additional shipped cells** (no quickstart E2 column; bench-scale splits and
results in docs/08; the train/test figures here are the script's quickstart-tier
defaults, not the bench splits):

| Dataset | Source | Task | Groups and choices | train / test | Primary metric |
| --- | --- | --- | --- | --- | --- |
| gsm8k | GSM8K (`openai/gsm8k` config `main`; val carved out of the train split) | math_qa numeric open-ended solving | none — the gold answer is the `#### <number>` value, rule-scored exact match, zero judge | 100 / 100 | accuracy |
| nextqa | NExT-QA (official `doc-doc/NExT-QA` annotations + the 6.5GB clip pack; the public mirrors hold the 1,570 val+test clips, so sampling runs within the supplied pack) | video_mcq temporal/causal selection | 5 options per question, one QA per video, each clip in exactly one split | 100 / 100 | accuracy |

A third extra, `mixed` (the `mixed/<method>` cells), is a zero-download
synthetic smoke dataset: seven per-sample modality combinations built locally by
`scripts/prepare_mixed_data.py` (its clip encoder needs PyAV:
`uv run --with av python scripts/prepare_mixed_data.py`), verified end to end per
combination on the scripted mock backend; it is not a benchmark column.

Seed prompts (task-layer defaults, the common starting point of the optimization
methods):

- mcq (pets / cub): `Classify the content of the target image.`
- kie (sroie): `{image}Extract the following fields from this image: {choices}` +
  `Respond with a JSON array of entity records. Output [] if none are present.`
- vqa (textvqa): `Answer the question about the target image with a short factual
  phrase (one to five words).` The short-answer clause is the task's output
  contract (KIE's JSON clause, same precedent): the first-line scorer grades a
  correct-but-verbose answer as 0
- math_qa (gsm8k): "Solve the math problem. Show your reasoning, then write the final
  answer on the last line exactly as Answer: <number>." The last-line contract is
  the scorer's parse target; the board is judgeless
- video_mcq (nextqa): `Classify the content of the target video.` One Question line
  plus the five options; demos carry no clip (engine media limits)
- mcq cot arms: add `assistant_prefix: "Let's think step by step."` on top of the seed
  template; mcq pairs with `judge: mcq_llm(variant=cot, classify_original_task=true)`
  (judge requests ≈×2); kie has no judge.
- vqa (textvqa): no judge (soft accuracy is rule-scored on the annotated answer
  list), and because `VqaTask` parses the **first non-empty line** as the answer, the
  CoT cell adopts an answer-first contract (short phrase on line 1, optional
  justification after), a deliberate deviation from the MCQ CoT cells, which may
  reason before the letter. textvqa is a full **E2 column** (8 methods × seeds
  42/43/44; table in §3); the demo-path strategies (ape / opro) render each demo's
  `question` natively, and label-bucket signals take the single-bucket degenerate path.

## 2. Experiment design

Unified weights Qwen3.5-9B (bfloat16), `prefetch_workers: 8` on the vllm arm
(the workers read/decode images, and on video datasets decode clips client-side
too; the backend mirrors `engine_kwargs.media_io_kwargs["video"]` into that
decoder); the
vllm engine profile is `enforce_eager + prefix_caching off +
max_num_batched_tokens 16384 + max_num_seqs 512` (`model_path` parameterized,
placeholder inside the config).

- **E1 backend parity**: raw / cot × two backends (vllm in-process,
  OpenAI-compatible API endpoint) × seed 42. The arms share weights, prompts and
  evaluation, and differ only in the client transport: `max_inflight` 512 with
  client-side prefetch (8 workers) on vllm; 16 with `sampling.thinking: false` on
  the OpenAI-compatible client, which sends local images inline as base64 data
  URLs and keeps `prefetch_workers` at its 0 default (no client-side read-ahead).
- **E2 seed stability**: 8 methods (sroie as 6) × seeds {42, 43, 44}, vllm arms.
  Method profiles: hill_climb 3 rounds × per_parent 2,
  opro 4 rounds, evoprompt 3 rounds (GA: the official N_P=10 initial pool ships
  in the config as 10 curated `strategy.seeds` prompts, bench cells inheriting
  them verbatim; an evoprompt GA cell whose pool holds < 2 distinct prompts is
  rejected at init), ape default 4 candidates in a single round, spo
  20 rounds, protegi 3 rounds; hyperparameters
  in the packaged spec (`src/eyas/spec`; the assembled `<ds>/<method>` cells). Every shipped cell pins its
  budget allocator explicitly: `budget.name` + the allocator's cap parameters
  (flat = parameterless, pinned with empty params; bandit = all four
  constructor parameters: `eval_rounds`/`samples_per_eval`/`c`/`keep_top`). No
  run's effective budget rides on an implicit constructor default
  (scan: `tests/configs/test_configs.py`). Note for the bandit cells (**config is
  law**): the runtime executes the configured window plan exactly and
  never rewrites a configured value; a pull starting at or beyond the split end
  fails fast with a `ValueError` carrying the arithmetic **and both remediation
  values** (`samples_per_eval ≤ n // eval_rounds`, `eval_rounds ≤
  n // samples_per_eval`). The shipped bench cells are correct by construction:
  the 14 cells on the 248-sample sroie/textvqa splits pin `8×31 = 248` exactly
  (the matrix spec's bandit combos), the cub 261 /
  pets 296 cells keep the official `8×32` (256 fits whole). The four quickstart cells are sized to
  their toy splits by the configurator:
  `eval_rounds=8` stays (paper structure) and
  `samples_per_eval = floor(n/8)`: pets `9` (74), cub `13` (110), sroie `12`
  and textvqa `12` (100), so all eight configured pulls serve full windows and
  the split tail (2/6/4/4) is never consumed (docs/baselines-fidelity.md §4.5
  D7/D8). The quickstart bases' budget block is inherited into every bench-scale
  cell through the matrix spec's base template, and the spec's bandit combos pin
  the bench caps explicitly (`32`/`32`/`31`/`31`), so toy-sized caps can never leak
  into the bench cells (bound in `tests/configs/test_matrix_configs.py`).
- **E3 cost profile**: wall / request count incl. the judge channel / input tokens
  (vllm arm, seed 42; see §5). Request counts cover
  evaluation + judge + optimizer generation requests passing the planner chokepoint;
  verdict usage rides `Verdict.usage` into `Cost.judge_requests/judge_input_tokens/
  judge_output_tokens` and response usage aggregates into token totals. A cell whose
  final loop pass was fully served by the run-dir record store bills zero (its bulk
  cost was billed on an earlier attempt of the same run dir); such cells are marked
  *(resume)* in §5 and their accuracies are exact (record-store replay).

E2 sweep order (the shipped 8-method set; sroie as its 6-method subset): raw →
cot → evoprompt → hill_climb → opro → protegi → spo → ape. The full-scale
benchmark (larger splits, 2B/4B/9B models, cost frontier) lives in docs/08.

5.4, cub 6.8, sroie 7.3, textvqa 9.7); single-seed rankings cannot be trusted;
always read results as mean ± σ.

**TextVQA** (test accuracy, n=100, seeds 42/43/44)

The column is three-seed. At n=100 single readings carry a ±4 to 5pp noise band;
the table is the mean, but the cot loss and the opro gain clear the band by
themselves.

| Method | test accuracy | Δ vs raw (pp) |
| --- | --- | --- |
| raw | 0.729 ± 0.002 |  |
| cot | 0.301 ± 0.006 | -42.8 |
| evoprompt | 0.787 ± 0.000 | +5.8 |
| hill_climb | 0.731 ± 0.004 | +0.2 |
| opro | **0.816 ± 0.003** | +8.7 |
| protegi | 0.742 ± 0.016 | +1.3 |
| spo | 0.793 ± 0.042 | +6.4 |
| ape | 0.784 ± 0.040 | +5.6 |

- **Gains ride the answer-format channel.** Several optimizers beat raw by
  +5.6 to +8.7pp, but the gains come from terseness and formatting (terse,
  well-formatted spans score higher under first-line soft matching), not better
  reading; on the judgeless span metric the prompt is where the model is cheapest
  to steer, so format gains are real and cheap here. What prompts still cannot buy
  is perception (cub) and the judgeless CoT tax below.
- **cot −42.8pp**: the direction is the same mechanism visible in the per-sample
  final-eval records of the seed-42 column (not the assistant-prefix; this cell
  does not use one):
  the *invitation* to justify poisons a judgeless span-match metric: justification
  leaks into the first line, and the careful-reading framing widens the answer span
  past the terse human annotation ("fort wayne" → "fort wayne indiana"). cot is a
  stable near-total collapse (σ 0.006), with every seed's first lines carrying
  prose. On judgeless open-ended tasks any reasoning affordance must stay strictly
  after a committed minimal-span first line, and even then it bought nothing.
- Cost: the loop bills the selection split only (the 100-sample test pass is
  accounted separately, final_eval reqs = 100/cell). Zero-judge column: the
  priciest loops are evoprompt / opro (1100 / 1600 reqs) while raw / cot bill
  100 each (§5).

## 4. E1 backend parity (seed 42, test)

Provenance: the same `quickstart` root and protocol as §3, the same run generation
as the E2/E3 tables. The OpenAI arm targets a `vllm serve`
process launched with the §2 engine profile on the same weights; that server-side
invocation is not part of this distribution (the shipped arm config sets only the
client: `base_url`, `model`, `api_key_env`), so the column is reproducible
client-side against any server serving those weights. The vllm column is the
§3 seed-42 cells verbatim.

| Dataset | Metric | Arm | vllm in-process | OpenAI-compatible API |
| --- | --- | --- | --- | --- |
| pets | accuracy | raw | 0.9099 | 0.9099 |
| pets | accuracy | cot | 0.9009 | 0.8739 |
| cub | accuracy | raw | 0.4864 | 0.4864 |
| cub | accuracy | cot | 0.4864 | 0.5227 |
| sroie | field_acc | raw | 0.8100 (strict 0.41) | 0.8100 (strict 0.41) |
| sroie | field_acc | cot | 0.8875 (0.60) | 0.8850 (0.59) |

Reading: parity is clean. Both raw rows and the sroie cot row sit inside ±0.5pp
across arms (pets raw and sroie raw are identical to four decimals in both). The
widest cell is cub cot (3.6pp): with per-arm binomial σ≈3.4pp (n=220), that sits
inside the expected spread of two independent draws, noise rather than divergence. No
systematic backend difference at any cell; E2/E3 keep the vllm in-process arm as
canonical.

Run-to-run batch-composition noise shows up too: for cot-style
long generations under continuous batching, numerical drift accumulates per decode
step with batch composition and near-tie greedy answers can flip; this is what
moves the pets cot row (vllm 0.9009 vs the OpenAI arm at 0.8739) while the raw
short-answer rows stay bit-exact.

## 5. E3 cost profile (vllm arm, seed 42)

Emitted by `scripts/aggregate_bench_results.py` from the seed-42 cells.
Cell format: `wall / reqs+judge / input-tokens` (`reqs` is the optimization-loop
bill incl. the judge channel; the shared final_eval test pass (the full test split
per dataset) is accounted separately and not included, doubled by the judge where
the cell protocol uses the LLM judge). *(resume)*: the final loop pass replayed
fully from the run-dir record store: the bulk was billed on an earlier attempt of
the same run dir; accuracies exact.

| protegi | 348s / 468+234 / 276.5k | 361s / 962+481 / 508.3k | 153s / 432+0 / 581.7k | 97s / 324+0 / 271.2k |

- **Judge channel confirmed**: on mcq datasets the judge bills exactly half of all
  loop requests (protegi pets `468+234`, one verdict per evaluation). KIE (sroie)
  and VQA (textvqa) are judge-free by design (rule-based scoring).
- **spo's zero judge requests is the protocol shape, not a defect**: its
  OvO selection votes ride the optimizer's *generate* channel (compare tier), already
  counted in `reqs`; the `judge_*` counters price only the EvalModel pairwise-judge
  channel, which spo does not use.
- Cheap tier raw / cot (100 reqs where billed; pets / cub raw / cot replayed at
  zero). On the judged (pets/cub) cells the mid tier is protegi / ape and the heavy
  tier spo / opro, with opro the most expensive optimizer there (1776-2860 reqs, half
  of it judge); on the judge-free columns sroie's top bills are evoprompt 1300 /
  hill_climb 1100, while textvqa's is opro 1600 (ahead of evoprompt 1100 /
  hill_climb 900).

## 6. spo notes

spo's selection is the paper's **reference-free one-vs-one (OvO) voting** (SPO, Findings of EMNLP 2025):
answer-vs-answer majority voting over the model's own answers: 4-vote ballots with
the ABBA side swap, unparsable/tie votes tallied 0.5 per side, votes riding the
generate channel's compare tier. The §3/§5 numbers come from that implementation.

## 7. Conclusions

1. **Backend parity holds** (§4, same run generation): across two
   backends × 6 configs no cell exceeds binomial noise. Both raw rows are
   bit-identical across arms and the widest cell (cub cot, 3.6pp) sits inside the
   expected spread of two draws.
2. **The method map differentiates by task form**:
   - Structured extraction (sroie): the biggest genuine gains of the matrix:
     hill_climb +8.0 / cot +7.7 field_acc (+18 / +17pp strict); few-shot families
     still trail the zero-shot pair (protegi +6.3, spo +3.5).
   - Near-saturated classification (pets): the seed prompt wins on every seed;
     every optimizer is net-negative (−1.5 to −4.5pp): on a strong 9B baseline the
     loop only spends its way down, and this is the matrix's clean
     "do-not-optimize" column.
   - Fine-grained long tail (cub): evoprompt +2.6pp is the one positive cell here;
     the rest of the field clusters at ±1pp around raw with
     protegi collapsing to −7.3pp: prompt search can find the format win but most
     operators are downside here.
   - Open-ended reading (textvqa): the judgeless span metric is format-steerable
     (opro +8.7 / spo +6.4 / evoprompt +5.8), while the CoT invitation collapses the
     answer-span contract (−42.8pp).
3. **Cost-effectiveness**: for sroie prefer cot first (+7.7pp at 100 reqs, zero
   judge), then hill_climb for the ceiling (+8.0pp / 1100 reqs); for pets use the
   raw seed prompt (every optimizer is net-negative); on cub evoprompt's +2.6pp is
   the only above-noise winner and costs mid-tier requests; take it only if you
   own the task family.
4. **Seed discipline**: cross-seed ranges reach 9.7pp on the small quickstart
   splits (§3) and seed std systematically underestimates long-generation drift
   (§4 note: read cot-style methods against a ±3pp band); never draw conclusions
   from single-seed gaps <2pp.

## 8. Reproduction guide

```bash
uv sync --extra vllm                # or --extra api
# The §3–§5 tables need the four E2 columns; --dataset is required (no default build).
uv run --extra prepare eyas prepare --dataset both --source auto   # pets + sroie
uv run --extra prepare eyas prepare --dataset cub --source auto
uv run --extra prepare eyas prepare --dataset textvqa --source auto
# --dataset all additionally builds the bench-only gsm8k / nextqa cells (docs/08);
# nextqa requires the user-supplied clip pack via --nextqa-videos (see below).
# data lands in datasets/quickstart/<ds>/{data,images}/; point each config's model_path
# (or, for the OpenAI arm, base_url / model) at a local Qwen3.5-9B

# A single run is the quickest smoke test — the cell assembles from the packaged spec
# (its directory is not read by the aggregator):
uv run eyas run --cell pets/raw --set run.seed=42
uv run eyas report --run outputs/quickstart_pets_raw/<stamp> --format md

# The §3/§5 tables are aggregated from one sweep per dataset × seed, written into the
# stems the script reads: <outputs-root>/qs_<ds>_s<seed>/NN-<run.name>.
# Sweep takes files, so export the cell grid first (gitignored GENERATED YAMLs,
# rendered from the same spec the assembled runs ride); then the block below —
# pets / seed 42 — repeats for <ds> in pets, cub, sroie, textvqa and <seed> in
# 42 43 44 (sroie has six methods — drop opro and ape).
uv run eyas gen-configs
uv run eyas sweep --output-root outputs/qs_pets_s42 --set run.seed=42 \
  --config configs/generated/pets_raw.yaml \
  --config configs/generated/pets_cot.yaml \
  --config configs/generated/pets_evoprompt.yaml \
  --config configs/generated/pets_hill_climb.yaml \
  --config configs/generated/pets_opro.yaml \
  --config configs/generated/pets_protegi.yaml \
  --config configs/generated/pets_spo.yaml \
  --config configs/generated/pets_ape.yaml
uv run python scripts/aggregate_bench_results.py quickstart-effect --dataset pets   # §3 table
uv run python scripts/aggregate_bench_results.py quickstart-cost                    # §5 rows

# §4 E1: the OpenAI-compatible arm goes into its own stem
# (qs_e1_openai_<ds>_s42); the vllm arm is the qs_<ds>_s42 sweep above.
uv run eyas sweep --output-root outputs/qs_e1_openai_pets_s42 \
  --config configs/generated/pets_raw_openai.yaml \
  --config configs/generated/pets_cot_openai.yaml
uv run python scripts/aggregate_bench_results.py e1-parity                          # §4 table
```

- E1 variants: the `<ds>/<method>` cells' `openai` variant
  (`<ds>` ∈ {pets, cub, sroie}, methods raw/cot; the openai arm's `base_url` / `api_key_env` point at
  any OpenAI-compatible endpoint; rendering is left to the server).
- The run directory is the checkpoint: `--resume <run_dir>` re-enters it
  (evaluation records persist per sample into `<run_dir>/cache/eyas.sqlite` keyed
  by (namespace, prompt_id, sample_id, split); a hit skips inference and judging);
  a sweep into the same `--output-root` reuses its deterministic per-cell
  directories. Changing judging / seeds / algorithm semantics requires a fresh run
  directory.
- Results land in `outputs/<run_name>/<stamp>/result.json` (keys: best / ranked /
  history / total_cost / cost_by_tier / final_eval; the primary metric is accuracy
  for pets/cub/textvqa and field_acc for sroie). Note: `--dataset all` additionally
  builds textvqa (3 parquet shards of ~310 MB, ~7 min via hf-mirror), gsm8k (HF
  `openai/gsm8k` via hf-mirror; pass `--source hf-mirror` where huggingface.co is
  unreachable) and nextqa (needs the local clip pack via `--nextqa-videos <zip|dir>`;
  its annotations come from raw.githubusercontent.com, or from
  `--nextqa-annotations <dir with train.csv/val.csv/test.csv>` where that host is
  blocked).

## 9. Known boundaries

- Single model (Qwen3.5-9B) × single budget tier × 3 seeds; the model-size and
  second-family coverage lives in docs/08 §4/§D, not in these tables.
- E3 is accounting-current: §3 and §5 come from the same quickstart run set
  on the build carrying judge-channel billing (`Cost.judge_*` from `Verdict.usage`,
  token totals from response usage; `report` surfaces `judge_reqs` / `in_tok` /
  `out_tok`), so the effect and cost tables share one generation. The §4 E1 table
  shares that run set with §3/§5 (see its provenance note); only the
  same-name cache replays listed next have non-representative wall values.
